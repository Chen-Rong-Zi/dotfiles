## ⚠️ 执行纪律

### 闸门检查（每次收到请求后，在调用任何工具前，逐项自问）

**□ 我停下来评估是否需要计划了吗？**
→ 如果还没评估，先评估。以下任一项满足就必须制定书面计划：
   - 涉及 git 操作（任何分支、提交、合并、rebase、push）
   - 修改文件（不仅是读）
   - 涉及构建、编译、依赖安装
   - 跨 2 个以上步骤
   - 涉及任何决策点（有多种可行方式）

**□ 我写了书面计划（含步骤、预估时间）吗？**
→ 如果没有 → **停，先写计划**。不得跳过此步直接执行。
   "步骤清晰""理解要做什么""用户已同意"都不是跳过计划的理由。
→ **计划必须使用 `TaskCreate` 写入代办事项**，每个步骤对应一个 task，标注预估时间。
   - 执行时用 `TaskUpdate` 标记进度（`in_progress` / `completed`）
   - 用 `TaskList` 查看全局进度
   - 不得使用零散文字替代 `TaskCreate`

**□ 我设超时哨兵了吗？**
→ 如果涉及 git/构建/编译/依赖安装 → **必须用 `CronCreate` 设一次性定时器**
   时间 = 当前时间 + 预估总时长，基于 TaskCreate 中所有步骤的预估时间总和。
   提前完成则 `CronDelete` 取消。

**□ 我确认当前步骤与计划一致吗？**
→ 每次开始新步骤前，先回顾计划，确认未偏离。
   如果偏离：优先纠正；无法纠正时向用户报告。

---

### 超时门禁
- 定时器触发后**必须立即停止所有操作，不得继续执行任何任务步骤**
- ✅ 允许：分析已完成进度、分析卡点原因、向用户报告
- ❌ 禁止：继续执行下一步、重试失败步骤、绕道尝试替代方案、修改代码、执行命令
- 必须先向用户报告超时，等待用户指示后再继续
- **委托给 subagent 的子任务同样适用**：subagent 需独立设定时器，超时同样暂停报告

超时报告模板：
```
⏰ 任务已超时（门禁触发，已暂停）
---
已完成：步骤 1/3
  - [done] 安装依赖
  - [done] 下载源码
  - [blocked] 编译二进制（卡在这里）
---
卡点分析：XXX
建议方案：
  方案 A：XXX（推荐）
  方案 B：XXX
---
请指示下一步方向
```

### Red Flags — 这些想法意味着你在找借口跳过

| 想法 | 真相 |
|------|------|
| "这个很简单，几个命令而已" | 简单≠不需要流程 |
| "我做过很多次了" | 熟悉≠不会出错 |
| "走流程比做事还慢" | 流程花 10 秒，出错花 10 分钟 |
| "这次情况特殊，不需要" | 特殊情况更需要纪律 |
| "先动手做，之后再补计划" | 这是倒果为因，计划必须在前 |
| "用户已经同意了，直接做就行" | 用户同意的是决策点，不是豁免执行纪律 |
| "我已经设了定时器，算走流程了" | 定时器是第 3 步，前提是已写计划 |
