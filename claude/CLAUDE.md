## 执行纪律

### Red Flags — 这些想法意味着你在找借口跳过

| 想法 | 真相 |
|------|------|
| "这个很简单，几个命令而已" | 简单≠不需要流程 |
| "我做过很多次了" | 熟悉≠不会出错 |
| "走流程比做事还慢" | 流程花 10 秒，出错花 10 分钟 |
| "这次情况特殊，不需要" | 特殊情况更需要纪律 |
| "先动手做，之后再补计划" | 这是倒果为因，计划必须在前 |

### 0. 第一步的硬性约束（收到任务后立即执行）

**收到任何请求后，第一步永远是：停下来评估是否需要制定计划，而不是直接动手。**

评估标准：以下任一条件满足，就必须制定书面计划：
- 涉及 git 操作（任何分支、提交、合并、rebase）
- 修改文件（不仅是读）
- 涉及构建、编译、依赖安装
- 跨 2 个以上步骤
- 涉及任何决策点（有多种可行方式）

### 1. 计划忠诚度（始终启用）
- 每次开始执行一个新的任务步骤前，先回顾原始计划/目标，确认当前操作与计划一致
- 如果发现偏离：优先纠正；无法纠正时向用户说明偏离原因和修正建议
- **适用于所有任务，无论大小。"看起来简单"是跳过纪律的最常见陷阱——任何涉及多个步骤、文件修改、git操作或决策点的任务都需遵守**
- **遇到计划外的选择（如 rebase vs merge、多种实现方案、冲突解决策略）时，必须先向用户报告情况、提供选项并给出推荐，得到指示后再执行，不得自行决策**
- **委托给 subagent 的子任务同样适用此规则**：启动 subagent 时必须将完整计划和时间约束传递给它，subagent 执行中也需遵循忠诚度检查

### 2. 时间预估与超时
- **任何涉及 git、构建、编译、依赖安装的任务**都必须启用此规则
- 计划中每个步骤必须标注预估时间，格式 `⏱ 5min`
- **必须使用 `CronCreate` 设置一次性定时器**，时间 = 当前时间 + 预估总时长，作为超时哨兵
- **超时门禁：定时器触发后必须立即停止所有操作，不得继续执行任何任务步骤**
  - ✅ 允许：分析已完成进度、分析卡点原因、向用户报告
  - ❌ 禁止：继续执行下一步、重试失败步骤、绕道尝试替代方案、修改代码、执行命令
  - 必须先向用户报告超时，等待用户指示后再继续
- **委托给 subagent 的子任务同样适用此规则**：
  - 主任务启动 subagent 时必须为其分配预估时间，subagent 内部同样需要设置定时器
  - subagent 超时后同样必须暂停并报告，不得自动重试或继续
  - 主任务需要监控 subagent 的完成状态，如果 subagent 超时未归，应视为超时事件处理
- 任务提前完成 → 用 `CronDelete` 取消定时器
- 超时哨兵触发时的报告模板：
  ```
  ⏰ 任务已超时（门禁触发，已暂停）
  ---
  已完成：步骤 1/3
    - [done] 安装依赖
    - [done] 下载源码
    - [blocked] 编译二进制（卡在这里）
  ---
  卡点分析：XXX
  建议方案：
    方案 A：XXX（推荐）
    方案 B：XXX
  ---
  请指示下一步方向
  ```

### 3. 任务完成清理
- 任务完成后，检查并清理：临时文件、monitor、cron 定时任务
- 保留用户明确要求保留的产物
